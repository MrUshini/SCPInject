# SCPInjectHealth

Экспериментальная Windows x64 DLL для чтения здоровья **своего** игрока в SCP: Secret Laboratory. Подготовлена по предоставленным файлам игры (пользователь указал версию 14.2.7). Работа внутри игры пока не проверена.

## Что делает DLL

После обычной загрузки DLL в процесс игры запускается поток, подключённый к IL2CPP. Он получает `ReferenceHub._localHub`, его `playerStats`, массив `_statModules` и значение `HealthStat.CurValue`. Используются экспорты `GameAssembly.dll`, имена классов и полей; адреса игровых методов не зашиты. Проверяются типы полей и возвращаемого значения.

Проверка выполняется каждые 250 мс. Изменения здоровья и состояния записываются в `%TEMP%\SCPInject-health.log`. До появления локального игрока DLL сообщает состояние ожидания. Отсутствие данных не выдаётся за нулевое здоровье. В главном меню или у наблюдателя наличие HealthStat не означает наличие живого персонажа.

## Сборка

Установите Visual Studio Build Tools с компонентом «Разработка классических приложений на C++». Откройте **x64 Native Tools Command Prompt**, перейдите в этот каталог и выполните `build.cmd`. Результат: `dist\SCPInjectHealth.dll`.

Альтернатива с MinGW-w64:

```sh
mkdir -p dist
x86_64-w64-mingw32-g++ -std=c++17 -O2 -Wall -Wextra -Werror -shared \
  -static-libgcc -static-libstdc++ src/health_reader.cpp \
  -o dist/SCPInjectHealth.dll -Wl,--no-insert-timestamp -static -lwinpthread
```

## Проверка в игре

DLL содержит точку входа для обычной загрузки Windows; отдельный инжектор в проект не входит. Наличие файла на диске само по себе не загружает его в игру. Manual mapping не проверен.

После загрузки в процесс игры откройте `%TEMP%\SCPInject-health.log`. В PowerShell можно следить за ним:

```powershell
Get-Content "$env:TEMP\SCPInject-health.log" -Wait -Tail 20
```

Ожидается сообщение `Local player HP: ...` после появления локального персонажа. Сравните число с интерфейсом игры, затем проверьте обновление после получения урона и лечения. Эти проверки требуют Windows и запущенной игры; в Linux выполнена только сборка и проверка структуры DLL.

Из другого кода **в том же процессе** доступны экспорты:

```cpp
BOOL GetLatestHealth(float* result); // TRUE: снимок здоровья получен; FALSE: данных нет.
BOOL IsHealthReaderRunning();
BOOL StopHealthReader();            // Сигнал остановки и ожидание до 5 секунд.
```

Не выгружайте DLL, пока `StopHealthReader()` не вернул `TRUE`. Функцию нельзя вызывать из `DllMain`. Для повторного запуска остановленную DLL нужно полностью выгрузить и загрузить заново. Вызов `GetLatestHealth` требует корректного указателя на доступную для записи память.

## Ограничения

Это прототип, не подтверждённая рабочая интеграция с SCP: SL. Поток читает живые объекты игры; переходы между сценами и завершение IL2CPP требуют проверки на Windows. Привязка потока к IL2CPP не гарантирует безопасность любого игрового getter вне основного потока Unity. При несовместимости классов, полей или методов смотрите сообщение в логе.

Файлы игры не включены в исходники и архив результата. Изменение здоровья, получение данных других игроков и обход механизмов защиты не реализованы.
